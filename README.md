# IZI TOUR — прототип нового сайта

Концепт-прототип сайта туроператора IZI TOUR (izi.tours): чартерные программы
из Минеральных Вод, Краснодара и Саранска в Турцию, Египет и Китай.

Это **не рабочий сайт**, а кликабельный прототип для защиты концепции.
Данные в нём демонстрационные (см. раздел «Что нужно заменить»).

## Как посмотреть

Файлы статические, сборка не нужна. Достаточно локального сервера:

```bash
cd izi-tour
python3 -m http.server 8080
# открыть http://localhost:8080
```

Открывать `index.html` двойным щелчком тоже можно, но часть браузеров
ограничивает работу с локальными файлами — сервер надёжнее.

## Структура

```
index.html              сайт для туристов
agentam.html            партнёрская программа (B2B)
kabinet.html            личный кабинет туриста
admin.html              редактор содержимого
manifest.json           паспорт приложения (PWA)
sw.js                   service worker: офлайн-режим кабинета
data/
  content.json          ВСЁ редактируемое содержимое сайта
  images.json           список доступных картинок (для редактора)
assets/
  css/site.css          стили главной, тема на CSS-переменных
  css/pages.css         стили отдельных страниц
  css/admin.css         стили редактора
  js/site.js            логика, схемы салонов, данные по умолчанию
  img/                  иллюстрации в формате WebP
```

## Кабинет как приложение (PWA)

Личный кабинет `kabinet.html` устанавливается на телефон как приложение.
Отдельной разработки нет — это тот же код плюс три файла: `manifest.json`,
`sw.js` и три иконки в `assets/img/`.

Что получает турист: иконку на домашнем экране, запуск без адресной строки
и, главное, **работу без интернета** — номер брони, документы, время вылета
и телефон представителя видны в аэропорту без сети. Сверху в этом случае
загорается жёлтая полоса «показываем сохранённую копию».

Как ставится:

- **Android** — браузер сам предлагает установку, в кабинете появляется
  кнопка «Сохранить на телефон».
- **iPhone** — Apple автоматического предложения не даёт, поэтому кабинет
  показывает подсказку: «Поделиться» → «На экран „Домой"».
- Если приложение уже установлено, блок меняется на «поездка сохранена».

Как устроен кэш (`sw.js`):

- страницы — сначала сеть, при отказе кэш;
- **`data/` и любые `.json` — только сеть**, при отказе кэш. Это важно:
  иначе после публикации в редакторе люди с установленным приложением
  видели бы вчерашние цены;
- стили, скрипты и картинки — сначала кэш, обновление в фоне.

При изменении логики кэширования нужно поднять версию `var V` в начале
`sw.js` — иначе у людей останется старый service worker.

**Уведомлений пока нет по-настоящему.** Обработчик `push` в `sw.js` написан,
но отправлять уведомления умеет только сервер, а GitHub Pages статический.
Заработает вместе с российским хостингом.

**Ограничения iOS**, которые нужно держать в голове: уведомления только
с iOS 16.4 и только после добавления на домашний экран; хранилище около
50 МБ и система чистит его при долгом неиспользовании. Поэтому офлайн-копия
не считается единственной — документы всё равно дублируются на почту.

## Редактор содержимого

Открывается по адресу `<адрес сайта>/admin.html`. Ссылок на него с сайта нет
и не должно быть, страница закрыта от поисковиков.

Что можно менять без программиста: города вылета и направления с ценами,
календарь дат, тексты и падежи курортов, отели со всеми полями, полётную
программу, ближайшие вылеты, раннее бронирование, дополнительные услуги,
вопросы про чартер, уровни постоянного туриста, коэффициенты размещения
и фотографии.

Как это работает:

1. Редактор читает `data/content.json` и показывает формы.
2. Правки сразу пишутся в черновик в браузере — можно закрыть вкладку и вернуться.
3. Кнопка **«Посмотреть»** открывает сайт с этими правками (`index.html?draft=1`),
   вверху появляется оранжевая полоса «ЧЕРНОВИК». На опубликованном сайте их ещё нет.
4. Кнопка **«Опубликовать»** записывает `data/content.json` (и новые картинки)
   прямо в репозиторий через GitHub API. Через минуту-полторы Pages пересобирает сайт.
5. Кнопка **«Скачать файл»** — запасной путь без ключей: файл кладётся в `data/`
   и отправляется обычным коммитом.

**Фотографии** перетаскиваются в раздел «Фотографии»: браузер сам уменьшает их
до 1600 px и пересохраняет в WebP. Имя файла становится ключом — кириллица
переводится в латиницу.

**Ключ доступа.** Для публикации нужен fine-grained token GitHub с правом
`Contents: Read and write` только на этот репозиторий. Он хранится в браузере
редактора. Это осознанный размен: ноль инфраструктуры против того, что ключ
лежит на компьютере менеджера. Не открывать редактор на общем компьютере;
при подозрении — отозвать токен на GitHub одной кнопкой. Когда сайт переедет
на свой сервер в РФ, вход станет обычным: логин и пароль.

**Что редактор не трогает и не должен.** Цены, свободные даты и остаток мест
в рабочей версии приходят из системы бронирования оператора автоматически.
Редактор — для того, что пишет человек: тексты, фотографии, расписание сезона,
акции, условия. Если менеджер вбивает цены руками, они устареют в тот же день.

**Три страницы, а не одна.** Условия для агентств и размер вознаграждения
намеренно вынесены с розничной страницы: покупателю тура незачем видеть,
сколько оператор платит партнёру. На `agentam.html` публично только «что даём»,
цифры высылаются вместе с договором. `kabinet.html` — личный кабинет туриста:
вход по телефону и коду, статусы документов, доплата остатка, допродажи.
Обе страницы подключают общий `site.css`, свой скрипт у каждой маленький
и лежит прямо в файле.

**Данные лежат в `data/content.json`** и правятся через `admin.html`.
Те же структуры продублированы в начале `site.js` как значения по умолчанию:
если `content.json` пропал или испорчен, сайт молча работает на них
и ничего не ломается.

**Нижняя панель** (`#mbar`) — единственный постоянный элемент поверх контента:
выезжает после первого экрана, показывает маршрут, дату, цену и кнопку брони,
прячется у формы заявки. Когда она выехала, на `body` появляется класс `barup`
и кнопки у нижнего края (мессенджеры, подборка, панель CRM) поднимаются,
чтобы ничего не перекрывалось.

**Тема** задаётся переменными в начале `site.css` (блок `:root`).
Светлый вариант собирается подменой полутора десятков значений —
переписывать стили не нужно. Класс `.dk` возвращает тёмные значения
внутри «кадров» (первый экран, сцена курорта, маршрут, схема салона, подвал).

Цвета текста, поверхностей и фирменные акценты вынесены в переменные и
используются через `var(--…)`. Остаются жёстко заданными только декоративные
оттенки внутри «картинных» блоков — небо маршрута, блики, градиенты кнопок:
в светлой теме они не меняются.

**Картинки** подключаются из объекта `IMAGES` в начале `site.js`.
Имена файлов совпадают с ключами: `bodrum_sea` → `assets/img/bodrum_sea.webp`.
Если файла нет, ключ остаётся пустым и интерфейс тихо откатывается
на общий макет курорта — ничего не ломается.

**Раннее бронирование** — в `EB` (этапы с датами и скидками, таймер считает до
ближайшей даты сам). **Программа постоянных туристов** — в `CLUB`.
**Бюджетный фильтр** направлений — `BUD` и `renderDeals()`.
**Рассрочка** пересчитывается функцией `perMonth()` из `INSTALL_M`.

**Посадочная страница** (`view-lp`) собирается функцией `lpRender()` из тех же
данных: заголовок, факты, отели и вопросы меняются вместе с выбранным городом
и направлением. Отдельной копии текстов нет. В шапке её нет намеренно — вход
контекстный, ссылкой под карточками направлений.

**Курорты** описаны в `RESORTS_DATA`, вылеты и цены — в `DATA`,
компоновки салонов — в `FLEET`, расписание сезона — в `PROG`,
ближайшие вылеты с остатком мест — в `SOON`, дополнительные услуги — в `ADDONS`,
коэффициенты размещения (доп. взрослый, ребёнок, малыш) — в `PAX_K`.

**Воронка** описана в `FUNNEL` (девять шагов), события пишутся через `track()`
и уходят в `dataLayer`. Итоговый пакет для CRM собирает `iziPacket()` —
в нём теперь есть состав семьи, выбранные допродажи и итоговая сумма поездки.
Типы заявок: `callback`, `booking`, `group`, `watch` (подписка на цену),
`agency` (турагентство).

## Чего ещё нет

- **Продолжить разбивку на страницы.** Агентства и кабинет уже вынесены.
  Дальше просятся расписание, раннее бронирование и постоянным туристам —
  адресами вида `/raspisanie/`, `/rannee-bronirovanie/`. Это и короче,
  и даёт точки входа из поиска.
- **Кабинет партнёра** — на `agentam.html` сейчас только вход-заглушка.
  Настоящий кабинет с ценами нетто, бронированием и взаиморасчётами —
  отдельная система.
- **Настоящая авторизация в кабинете туриста** — сейчас подойдёт любой
  код из четырёх цифр.
- `robots.txt` и `sitemap.xml` — не нужны прототипу под `noindex`, нужны рабочей версии
- Кабинет турагентства с ценами нетто (сейчас только форма заявки)
- Реферальная механика «приведи друга»
- Посадочные страницы под каждую пару «город вылета × страна»
- Яндекс.Метрика с целями на всех девяти шагах воронки
- Горы Аватара: вкладки «Города» и «Вечер»
- Мобильный первый экран: нужен вертикальный кадр 3:4
- Салоны изнутри для всех трёх типов ВС

## Технические заметки

- Одна страница, без сборки и зависимостей. Внешне подключается только
  Google Fonts (Onest + Playfair Display).
- У курортов есть падежные формы: `n` именительный, `acc` винительный,
  `gen` родительный, `prep` предложный — тексты собираются без «до Бодрум».
- Проверено на ширинах 360–1440 px, горизонтального переполнения нет,
  в консоли нет ошибок и 404 по картинкам.
- Все внутренние ссылки относительные — сайт живёт в подпапке `/izitours/`.
  Абсолютные адреса только там, где так положено: `canonical`, `og:url`, `hreflang`.
- Учитывается системная настройка «уменьшить движение»: анимации отключаются.
- Хостинг для боевой версии должен быть в РФ — 152-ФЗ и доступность.
